# Moto g13 acceptance, 2026-10-09

## Source and method

PRs #57 and #58 were merged at the owner's explicit request. Combined main:
`03042160f5673338d04cc668b179fae0ce0cbaa5`. Both main checks succeeded:
[Current App CI](https://github.com/stupidsavacan/Clocky/actions/runs/37905502955),
[Reference APK Guard](https://github.com/stupidsavacan/Clocky/actions/runs/37905502936).

The debug-only `Phase3DeviceInstrumentation` runner was built and tested from
`daee072a3d1ba2be6c925459243533261949251c`, based on that main. It adds no production
renderer or production behavior. It injects actual two-pointer touchscreen MotionEvents through
Android UiAutomation into Studio, including pointer down/up, reordered indices and CANCEL.
This is system input on the physical phone, not a single-pointer cdev drag or a human-finger trial.
The Info case supplies an unsaved draft through Studio's existing draft intent contract.

Phone access used Broker v2 supervised FIFO leases and cdev only. Existing widget ID23 was
retained. No widget Save, uninstall, data clear, launcher-widget deletion or external share occurred.
The owner-required `moto g13 - Clocky owner control` window remained open and was not controlled.

## Successful cases

Three runs returned `clocky-summary=PASS`, `INSTRUMENTATION_CODE: -1`, each with 10 passed
cases: IDs 0/1 in stable order, IDs 0/1 with reordered MOVE indices, and IDs 7/9 with reordered
MOVE indices. The 30 results are repetitions across three pointer configurations, not 30 unique cases.

Each run verified:

- Time expansion 120 to 180sp and contraction 120 to 90sp.
- CANCEL after expansion restored the exact original draft.
- Date expansion 16 to 24sp.
- Simulated 2x1/3x2/4x3/4x4 cells selected Strip/Card/Large/Square without changing requested design.
- Square-only Time expansion changed exactly the scoped DesignEdits state.
- Draft Info expansion to 21.6sp.

Every completed pinch asserted exact full DigitalDesign equality against DesignEdits using the
actual coordinate-span ratio. One Undo restored the entire preceding design; Redo restored the
result, and a final Undo returned to the original draft. Production RemoteViews/PreviewHost child
and frame bounds were checked during intermediate MOVE rendering and simulated class changes.
The bounds check allows one pixel solely for integer layout rounding; model assertions have no tolerance.
This is geometry verification, not a glyph screenshot comparison or frame-performance measurement.

## Failed experiments and handoff

Injection with IDs 7/19 failed on this phone in both stable and reordered configurations. Sender
traces contain correct second-pointer coordinates, but the Window callback observed pointer19 at
Y=0 and X shifted by one pixel. The resulting span change did not cross pinch slop. The cause in the
system injection path is unresolved; no production fix or weakened assertion was made. This does
not establish physical pointer19 behavior. Failed instrumentation results are retained alongside passes.
An earlier runner argument-parsing failure was also retained and corrected in the debug fixture.

Unit6 exhausted its hold duration. The restoration hook failed before HOME, and the independent
comparison correctly marked the Broker DIRTY: saved settings were byte-identical, widget ID23
remained, but the visible widget size class was unknown because the launcher was not visible.
A finite explicit recovery returned HOME and compared against the original saved baseline;
recovery `e1500230344b4fbabbfba3a9ec59afa6` ended with **clean release, exit0**. The owner window
was retained under the owner's explicit exception and the recovery reason recorded this exception.
No registry/lock editing or baseline replacement was used.

The installed stock main APK was verified by the handoff as SHA256
`a59e1d4ad453283b10c51af4f76d2f126f37ea7a0cdae9e51da1c62b52d1d254`, source main0304216.
It was built locally using the existing debug signing identity and reinstalled without uninstalling.

Final debug fixture `lintDebug` and `assembleDebug` passed. Raw local evidence and credentials remain
under ignored build/device; credentials, device identifiers and full device screenshots are not published.

## Import/export integration smoke

allocating a launcher widget or saving widget storage. Import opened Android DocumentsUI's picker,
Export opened its document creation picker, and file Share opened Android's ChooserActivity through
the production exchange controller. Each was cancelled; no file was selected/written and no share
recipient was chosen. This verifies native activity launch/cancel, not an import/export file round trip.
The first attempt used ID0 and exited to the launcher; that failed smoke was preserved, not counted
as a pass. The fresh ID999 run passed all four screen checks.

Final FIFO unit `e27be7b5e37b4d448b9db315fc554d32` ended with **clean release, test exit0**.
Broker status was subsequently verified **FREE**, recovery_required=false. Baseline checks preserved
widget ID23, byte-identical settings and original launcher geometry. The retained APK is stock main0304216.
