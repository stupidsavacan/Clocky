# Clocky compile bootstrap handoff

This document records the ownership boundary for the current AOSP DeskClock-based app during the compile-bootstrap phase.

## Build ownership

### A — Web/runtime self-acquirable tools

Use official upstream distributions when a local Web runtime needs them; do not place these in the repository or a Clocky-specific bundle merely for convenience.

- JDK 17
- Gradle distribution selected by the checked-in wrapper
- generic Android command-line tools when a one-off local diagnostic needs them

### B — GitHub Actions is the authoritative resolver/builder

The clean Linux runner owns resolution and verification of:

- Android SDK platform 35
- Android Build Tools 35.0.0
- checked-in Gradle wrapper validation
- Android Gradle Plugin 8.7.3
- Kotlin Gradle Plugin 2.0.21
- AndroidX / Material and all transitive Maven dependencies
- Linux AAPT2 selected by AGP
- unit tests
- Android lint
- `assembleDebug`
- debug APK checksum and build metadata

The obsolete MVP build/sign workflow is not evidence that the current `app/` builds.

### C — Clocky offline bundle

Deferred for the first compile-bootstrap PR. Do not create a large dependency cache until the authoritative Actions clean build is stable and a local Web build would materially shorten iteration time.

If created later, it must be generated by Actions, kept as a short-lived private artifact, contain no source or signing material, and be verified in a clean job with `--offline assembleDebug`.

### D — Desktop-only material and runtime validation

Never request, upload, or commit these as part of the Web/Actions bootstrap:

- ADB/device access
- emulator or physical-device state
- launcher/AppWidget runtime evaluation
- Google Clock reference APK or extracted proprietary assets
- production/release JKS
- signing passwords
- release signing and final release decision

## Desktop runtime checklist

After receiving an APK built from a known commit, Desktop should validate:

- [ ] install/upgrade via ADB and normal launch
- [ ] startup crash/ANR and relevant logcat
- [ ] Alarm create/edit/enable/disable
- [ ] alarm firing, dismiss and snooze
- [ ] exact-alarm access behavior on the test Android version
- [ ] notification permission and notification channels
- [ ] full-screen alarm behavior and lock-screen presentation
- [ ] reboot / locked-boot restoration
- [ ] time and timezone changes
- [ ] locale changes and RTL smoke test
- [ ] 12/24-hour mode changes
- [ ] Timer create/run/pause/reset/expiry
- [ ] Stopwatch start/pause/reset/laps
- [ ] World Clock city selection and timezone display
- [ ] Digital/Analog AppWidget add and update
- [ ] AppWidget resize, launcher rebind/restore and tap destinations
- [ ] dark/light mode and font-scale smoke tests
- [ ] Google Clock side-by-side screenshots and measurements
- [ ] release signing/upgrade compatibility only after runtime acceptance

## Handoff evidence

Every Desktop test target should identify:

- Git commit SHA
- CI run URL
- APK SHA-256
- toolchain metadata
- unit-test result
- lint result
- `assembleDebug` result

Device-only failures return to the Web/source owner as a reproduction recipe plus logcat/screenshots/device and launcher information; source fixes should then be reproduced in CI before another Desktop pass.
